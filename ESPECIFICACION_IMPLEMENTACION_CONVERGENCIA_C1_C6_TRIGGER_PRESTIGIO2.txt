======================================================================
1. OBJETIVO DEL BLOQUE
======================================================================

Construir Convergencia normal como una capa completa de seis circuitos, contando
Pulso de Arranque como C1.

El recorrido termina al estabilizar C6. No existe C7 en esta versión. Al terminar
C6 se registra un evento desconocido visible como "???". Este evento será el
detonante de Prestigio 2 en una actualización futura, pero esta implementación NO
debe crear Prestigio 2, Lambda nueva, Convergencia Profunda, Dimensión 4 ni ninguna
mecánica posterior.

Resultado esperado de esta versión:

1. C1 ya existente se migra al sistema genérico.
2. Se añaden C2, C3, C4, C5 y C6.
3. La placa 5x5 se convierte en una red real de conectores ortogonales.
4. Cada nuevo circuito requiere un ciclo normal completo de Convergencia.
5. C6 debe colocarse, quedar energizado y estabilizarse antes de activar "???".
6. Después de C6 no se puede reconstruir otro Receptor ni producir estabilidad
   para una recompensa inexistente.
7. El jugador puede consultar la placa final y el archivo de circuitos, pero no
   iniciar C7 ni editar la placa mediante una Convergencia sin recompensa.

2. CANON QUE NO SE DEBE CAMBIAR
======================================================================

- Existen juego base, D1, D2 y D3.
- Las dimensiones son independientes y conservan su progreso en Convergencia.
- No existe D4 planificada actualmente.
- El progreso offline general mantiene el límite inicial de 12 horas.
- Cada ciclo de Convergencia reinicia juego base, recursos base, edificios y
  mejoras reconstruibles, progreso operativo de la Máquina, Receptor, señales y
  estabilidad.
- Cada ciclo conserva D1, D2, D3, automatizaciones D3, objetos finales,
  d1TreePoints, circuitos poseídos, configuración estabilizada y telemetría
  permanente.
- Después de cada reset se debe redescubrir/reconstruir la Máquina, alcanzar 80%,
  activar Prestige1Prepared/Canal de Convergencia y reconstruir el Receptor.
- Actividades anteriores a la reconstrucción del Receptor no se acreditan de
  forma retroactiva.
- D1 activa/aporta mediante exploraciones y misiones coordinadas.
- D2 activa/aporta mediante peregrinaciones completadas.
- D3 activa/aporta mediante trabajos de piezas y ensamblaje.
- Las tres señales deben estar activas, incluso si la estabilidad ya llegó al
  límite.
- Prestigio 2, Convergencia Profunda y narrativa definitiva quedan fuera.

======================================================================
3. RECORRIDO EXACTO DE UN CICLO
======================================================================

Estados visibles propuestos:

REBUILDING
  El jugador reconstruye juego base y Máquina.

SYNCHRONIZING
  Máquina desbloqueada, 80%, Canal activo y Receptor reconstruido. Se aceptan
  fuentes persistentes de D1/D2/D3.

READY
  Tres señales activas y estabilidad requerida alcanzada. No se aceptan más
  fuentes para este ciclo.

CONFIGURING
  Se entrega exactamente un circuito. La configuración estabilizada anterior
  continúa activa. El jugador edita un borrador.

COMMIT_PREPARED
  Estado transaccional persistente y no visible. Contiene todo lo necesario para
  terminar el reset de forma idempotente.

REBUILDING DEL SIGUIENTE CICLO
  Borrador promovido a configuración activa, snapshot aplicado, reset completado
  y completedCycles fijado exactamente al ciclo objetivo.

COMPLETED
  Solo después de estabilizar C6. No hay siguiente premio ni sincronización.

Flujo completo:

1. Reconstruir juego base/Máquina.
2. Llegar a 80% de reparación.
3. Activar Canal de Convergencia (Prestige1Prepared).
4. Reconstruir Receptor.
5. Activar señales D1/D2/D3 con una actividad válida posterior al Receptor.
6. Llenar estabilidad.
7. Entrar en configuración y recibir el siguiente circuito por orden.
8. Colocar/rotar circuitos en el borrador.
9. Resolver placa y mostrar preview de efectos.
10. Confirmar y estabilizar.
11. Guardar intent transaccional.
12. Ejecutar reset exactamente una vez.
13. Promover borrador/snapshot.
14. Entrar al siguiente ciclo o completar C6.

4. FÓRMULA DE ESTABILIDAD Y VALORES PROVISIONALES
======================================================================

Mantener la fórmula experimental actual:

requiredStability = ceil(120 * (1 + 0.55 * ownedCircuitCount)^2)

ownedCircuitCount se mide ANTES de recibir el siguiente circuito.

Tabla exacta:

Premio    Poseídos antes    Estabilidad    Trabajo base equivalente
C1        0                 120             600 s  = 10.0 min
C2        1                 289            1445 s  = 24.1 min
C3        2                 530            2650 s  = 44.2 min
C4        3                 843            4215 s  = 70.3 min
C5        4                1229            6145 s  = 102.4 min
C6        5                1688            8440 s  = 140.7 min

Conversión base:

baseStability = max(0, baseWorkSeconds) / 5.0

Con C3 activo:

creditedStability = baseStability * activeSnapshot.stabilityGainMultiplier

El multiplicador se aplica al aporte NUEVO, nunca:

- a estabilidad ya guardada;
- al requisito;
- a una fuente procesada previamente;
- dos veces online/offline;
- antes de verificar sourceId.

Orden obligatorio al acreditar:

1. Validar fase SYNCHRONIZING.
2. Validar Receptor.
3. Validar dimensión y sourceId.
4. Rechazar sourceId duplicado.
5. Calcular segundos base.
6. Aplicar multiplicador del snapshot activo.
7. Limitar al requisito.
8. Registrar sourceId.
9. Activar señal si corresponde.
10. Si se alcanza el requisito y están las tres señales, pasar a READY y fijar
    synchronizationReadyUnix una sola vez.

No redondear cada actividad a entero. Guardar double. La UI puede mostrar un
decimal; la comparación debe usar el valor double real con cap exacto.

-----------------------------------------------------------------------
C1 — PULSO DE ARRANQUE
-----------------------------------------------------------------------

Forma base: terminal de un conector.
Efecto base: +0.10 al canal baseLE.

Regla especial únicamente durante su tutorial inicial:

- Debe estar adyacente al Núcleo y orientado/conectado hacia él.

Después de estabilizar C1, esa obligación deja de ser universal. En ciclos
posteriores C1 puede recibir energía mediante C2/C3/C4/C6. Si está desconectado,
su efecto queda inactivo, pero la placa puede confirmarse con advertencia cuando
la regla del circuito recién obtenido sí se haya demostrado.

-----------------------------------------------------------------------
C2 — ENLACE AXIAL
-----------------------------------------------------------------------

Forma base: dos conectores opuestos N+S. La rotación 90/270 produce E+W.
Regla nueva: transmite energía en línea recta.
Efecto base: +0.10 al canal baseTraces.

Tutorial sugerido:

Núcleo -> Enlace Axial -> Pulso de Arranque

La UI debe mostrar que Pulso puede funcionar sin tocar el Núcleo directamente.

-----------------------------------------------------------------------
C3 — CODO RESONANTE
-----------------------------------------------------------------------

Forma base: dos conectores adyacentes N+E.
Rotaciones producen E+S, S+W o W+N.
Regla nueva: cambiar la dirección de la ruta.
Efecto base: +0.10 al canal stabilityGain.

El efecto se aplica únicamente a estabilidad nueva y debe coincidir online y
offline.

-----------------------------------------------------------------------
C4 — DISTRIBUIDOR TRIAXIAL
-----------------------------------------------------------------------

Forma base: tres conectores N+E+W (T).
Regla nueva: bifurcar la red.
Efectos base:

- +0.12 al canal baseLE.
- +0.12 al canal baseTraces.

No exigir que sus tres puertos tengan vecino para quedar energizado. Basta una
ruta al Núcleo. Sin embargo, su tutorial debe pedir usar la T para mantener
energizados al menos dos circuitos terminales/rutas. El resolvedor debe informar
degree/conexiones para comprobar que la demostración tutorial ocurrió.

-----------------------------------------------------------------------
C5 — ACOPLADOR LOCAL
-----------------------------------------------------------------------

Forma:

- Un conector de alimentación.
- Una flecha de objetivo independiente del conector.
- La flecha rota junto con la pieza.

Regla nueva: relación de vecindad explícita.

Condiciones para activar su efecto:

1. C5 está energizado por su conector.
2. Existe un circuito energizado en la celda señalada por la flecha.
3. El objetivo no es C5.
4. El objetivo no es otro amplificador/acoplador.
5. Solo se aplica una vez.

Efecto provisional:

Añade +0.05 al canal primario del objetivo.

Canal primario fijo por definición:

- C1 -> baseLE.
- C2 -> baseTraces.
- C3 -> stabilityGain.
- C4 -> baseLE. No copia también su bonus secundario de Trazas.
- C6 no puede ser objetivo durante esta versión.

No usar porcentaje del porcentaje. Es un bonus fijo de cinco puntos porcentuales.
Ejemplos:

- C5 apunta a C1: C1 aporta +0.15 LE en total.
- C5 apunta a C2: C2 aporta +0.15 Trazas.
- C5 apunta a C3: C3 aporta +0.15 estabilidad.
- C5 apunta a C4: el canal primario LE de C4 pasa de +0.12 a +0.17; Trazas
  permanece +0.12.

No existe amplificación transitiva, recursiva ni encadenada.

-----------------------------------------------------------------------
C6 — MATRIZ DE CIERRE
-----------------------------------------------------------------------

Forma base: cuatro conectores N+E+S+W (cruz como un único nodo, sin separación
de canales).

Condiciones de activación:

1. C6 está colocado dentro de la placa.
2. C6 está energizado.
3. Los seis circuitos C1–C6 están colocados.
4. Los seis circuitos están energizados.
5. No existen colisiones ni placements inválidos.

No exigir coordenadas exactas ni una solución única.

Efectos provisionales de cierre:

- +0.08 al canal baseLE.
- +0.08 al canal baseTraces.
- +0.05 al canal stabilityGain.

Estos efectos se aplican al snapshot final, aunque ya no exista otro circuito.
Siguen siendo útiles para progreso base y para la futura actualización.

Solo al estabilizar una configuración donde C6 cumpla todas sus condiciones se
marca Convergencia normal como completada y se dispara "???".

======================================================================
6. AGREGACIÓN DE EFECTOS
======================================================================

Para esta versión usar suma de bonuses dentro de cada canal y una multiplicación
única en el consumidor:

baseLEMultiplier       = 1.0 + clamp(sumBaseLEBonuses,       0.0, 1.00)
baseTracesMultiplier   = 1.0 + clamp(sumBaseTracesBonuses,   0.0, 1.00)
stabilityGainMultiplier= 1.0 + clamp(sumStabilityBonuses,    0.0, 0.50)

No multiplicar circuito por circuito. No depender del orden del catálogo.

Ejemplo final sin C5:

LE:          1 + 0.10 C1 + 0.12 C4 + 0.08 C6 = x1.30
Trazas:      1 + 0.10 C2 + 0.12 C4 + 0.08 C6 = x1.30
Estabilidad: 1 + 0.10 C3 + 0.05 C6          = x1.15

Ejemplos con C5:

C5 -> C1: LE x1.35, Trazas x1.30, Estabilidad x1.15.
C5 -> C2: LE x1.30, Trazas x1.35, Estabilidad x1.15.
C5 -> C3: LE x1.30, Trazas x1.30, Estabilidad x1.20.
C5 -> C4: LE x1.35, Trazas x1.30, Estabilidad x1.15.

Todos los valores deben ser finitos y no negativos. Si un save contiene NaN,
Infinity o magnitud fuera de límites, rechazar el snapshot y conservar/restaurar
el último snapshot válido.

Aplicación:

- LE online y offline leen GetBaseLEProductionMultiplier().
- Trazas online y offline leen GetBaseTracesProductionMultiplier().
- Todas las fuentes D1/D2/D3 leen GetStabilityGainMultiplier().
- Cada multiplicador se aplica una sola vez.

7. REGLAS DEL TABLERO Y RESOLVEDOR
======================================================================

Placa fija: 5x5.
Coordenadas válidas: x,y entre -2 y +2.
Núcleo fijo y reservado: (0,0).

Máscaras recomendadas:

North = 1
East  = 2
South = 4
West  = 8

Rotación horaria:

N -> E -> S -> W -> N

Reglas:

- Una pieza ocupa una celda.
- Solo conexiones ortogonales.
- Dos vecinos conectan si ambos poseen conectores recíprocos.
- El Núcleo ofrece energía por sus cuatro lados.
- Un circuito está energizado si pertenece al componente alcanzable desde el
  Núcleo.
- Resolver mediante BFS o DFS con conjunto de visitados.
- Los bucles físicos pueden existir, pero no dan bonus especial y no multiplican
  efectos.
- Conectores abiertos no invalidan la placa.
- Circuitos desconectados permanecen inactivos.
- No hay intensidad, consumo, capacidad, colores, diagonales, wrap, piezas
  multicelda ni cruces separados.

El resolvedor debe ser una función pura:

ResolveBoard(definitions, placements) -> ConvergenceBoardResolution

Entrada:

- catálogo/revisión;
- placements del borrador o configuración activa;
- ninguna dependencia de GameObject, UI, SaveService o singletons.

Salida mínima:

- bool structurallyValid;
- errores globales;
- resultado por circuito: colocado, rotación, portMask rotado, vecinos
  conectados, energized, Manhattan distance, degree, motivo de inactividad;
- activeCircuitIds;
- resolved contributions por circuito/canal;
- candidateSnapshot;
- deterministic layoutHash.

La misma entrada debe producir la misma salida independientemente del orden de
las listas.

Orden de resolución obligatorio:

1. Validar catálogo, IDs, coordenadas, rotaciones, Núcleo y colisiones.
2. Rotar máscaras.
3. Crear enlaces recíprocos.
4. Calcular energizados desde el Núcleo.
5. Calcular propiedades espaciales.
6. Aplicar contribuciones base C1–C4/C6.
7. Aplicar C5 una sola vez.
8. Evaluar condición global C6.
9. Agregar canales y aplicar caps.
10. Generar snapshot/hash determinista.

Nunca escribir if especiales de C1–C6 dentro de PrestigeUI. Las reglas declarativas
de forma y efectos viven en catálogo/resolvedor.

======================================================================
9. MIGRACIÓN DE SAVES
======================================================================

La migración ocurre ANTES de normalizar.

Casos mínimos:

1. Save sin ConvergenceState:
   Crear estado inicial C1 no poseído, nextAwardOrdinal=1.

2. Save actual sin circuitos:
   Conservar sincronización válida; nextAwardOrdinal=1.

3. Save con Pulso poseído y placa estabilizada:
   Mantener C1, convertir boardPlacements a committedPlacements, conservar snapshot
   legado válido y fijar nextAwardOrdinal=2.

4. Save con ConfigurationPending:
   Configuración estabilizada previa permanece activa. boardPlacements pasa a
   draftPlacements. No perder C1 ni darlo otra vez.

5. ID desconocido:
   Conservar ownership y placement en estado Unavailable/cuarentena. No eliminar.

6. Coordenada/rotación inválida:
   No dejarla participar en el resolvedor. Moverla a cuarentena diagnóstica y
   conservar el último snapshot activo.

7. Versión futura:
   No rebajar progressVersion ni sobrescribir el save. Abrir modo seguro o abortar
   carga con backup y mensaje claro.

8. Migración repetida:
   Debe ser idempotente.

No recalcular automáticamente snapshots estabilizados antiguos con números nuevos.
Conservar su catalogRevision y aplicarlos hasta la próxima estabilización.

10. GUARDADO ATÓMICO
======================================================================

SaveService.Save() debe devolver bool o resultado explícito. No ignorar errores.

Secuencia recomendada:

1. Construir SaveData completo.
2. Serializar a JSON.
3. Escribir save.json.tmp en la misma carpeta.
4. Flush del stream al disco.
5. Deserializar el temporal y validar que no sea null/ilegible.
6. Si existe save.json, reemplazarlo atómicamente y mantener save.json.bak.
7. Si no existe, mover temporal a save.json.
8. Reportar éxito/fallo.

En Windows puede usarse File.Replace(temp, SavePath, BackupPath, true) cuando el
destino existe. Debe existir fallback seguro para plataformas donde no esté
disponible. Nunca borrar el save anterior antes de validar el temporal.

Load:

- Intentar save.json.
- Si está truncado/ilegible, intentar .bak.
- Informar recuperación.
- No ejecutar mutaciones destructivas antes de tener managers cargados.

Mover ConvergenceCircuitSystem.RecoverTransaction(GameState.I) para que ocurra
DESPUÉS de MachineManager.I.LoadProgressFromSave(data) y de cargar las autoridades
que el reset pueda modificar.

======================================================================
11. TRANSACCIÓN DE PREMIO Y CONFIRMACIÓN
======================================================================

Entrega del circuito:

1. Verificar phase == READY.
2. Obtener definición por nextAwardOrdinal.
3. Si ordinal > 6 o normalConvergenceCompleted, rechazar.
4. Si circuito ya poseído, no duplicar; reconstruir estado Configuring.
5. Añadir ownership con acquiredCycle.
6. Copiar committedPlacements a draftPlacements.
7. Añadir circuito nuevo a inventario, sin colocarlo automáticamente salvo que la
   UX use una disposición sugerida explícita.
8. phase = CONFIGURING.
9. Guardar atómicamente.

Edición:

- Solo modifica draftPlacements.
- activeSnapshot y committedPlacements continúan funcionando.
- Mover, rotar o retirar no cuesta recursos.
- Guardar borrador después de cada acción o con debounce corto y guardado forzado
  al salir/cerrar.

Confirmación:

1. Resolver borrador sin mutar estado global.
2. Requerir estructura válida.
3. Requerir circuito recién entregado colocado y energizado.
4. Para C6, requerir todos C1–C6 colocados y energizados.
5. Otros circuitos poseídos pueden estar inactivos con advertencia persistente y
   confirmación secundaria. C6 es la excepción global.
6. Crear transactionId único.
7. targetCompletedCycles = completedCycles + 1. Nunca usar ++ durante recovery.
8. Guardar journal COMMIT_PREPARED con layout/snapshot candidato.
9. Si guardar falla, no resetear.
10. Ejecutar ResetGameBaseForConvergence de forma idempotente.
11. Resetear Receptor/señales/estabilidad/sourceIds de forma idempotente.
12. Registrar telemetría una vez para transactionId.
13. Promover draft a committed y candidateSnapshot a activeSnapshot.
14. completedCycles = targetCompletedCycles.
15. nextAwardOrdinal = ordinal entregado + 1.
16. Si ordinal == 6, completar endpoint descrito en sección 13.
17. Si no, phase = REBUILDING.
18. Guardar estado final atómicamente.
19. Limpiar journal y guardar/confirmar según estrategia escogida.

Recovery:

- Si existe pendingTransaction, usar targetCompletedCycles y flags, no incrementos.
- Repetir cualquier etapa debe dejar exactamente el mismo resultado.
- No duplicar circuito, reset, completedCycles, telemetría ni evento "???".

13. ENDPOINT C6 Y EVENTO "???"
======================================================================

Momento exacto del evento:

NO se activa al llenar estabilidad de C6.
NO se activa al entregar C6.
SÍ se activa después de confirmar una placa válida con C6 y completar el commit
transaccional del sexto circuito.

Al completar C6 fijar de forma persistente:

- normalConvergenceCompleted = true
